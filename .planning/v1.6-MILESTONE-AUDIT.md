# Milestone v1.6 "Mobile Experience Redesign" — Audit Report

**Audited:** 2026-08-11T05:15:00.000Z
**Status:** gaps_found
**Scope:** Phases 20-23 (HOME-13, HOME-14, HOME-15, HOME-16, PORT-07, EDN-10, EDN-11, ABOUT-05, UI-02)

## Summary

This milestone was already reconciled once at the tracking-artifact level (STATE.md/ROADMAP.md/REQUIREMENTS.md, 2026-08-10) after discovering that Phase 21's shipped implementation had been superseded by an undocumented direct commit (`6c51695`), Phase 22 was cancelled, and Phase 23 was delivered outside the plan/execute cycle. That reconciliation correctly recorded WHAT happened at each phase. This audit checks something that reconciliation did not: whether the actual, currently-shipped, cross-phase runtime behavior still satisfies every requirement — not just whether the paperwork is consistent.

It found one real regression: **HOME-16 (per-visit random accent color) no longer works at phone width.** The randomization logic still runs, but the same commit that swapped the phone-width homepage renderer (`HomeCarousel` → `MobileHomePrototype`) did not carry the accent-randomization wiring over, and the existing automated test for this requirement (`homepage-accent-random.spec.ts`) is structurally blind to the regression because it only ever runs at desktop width.

Everything else genuinely holds: HOME-13 (mobile nav), HOME-14/HOME-15 (scroll-driven homepage journey, now via `MobileHomePrototype`), and cross-page header consistency (Homepage/Gallery/Édition) are all wired correctly and pass their full e2e coverage (61/61 relevant assertions, independently re-run for this audit, not read from a prior report).

## Cross-Phase Integration (gsd-integration-checker findings, independently spot-checked)

**Wired correctly:**
- HOME-13: exactly one nav surface reaches a phone visitor — `MobileHomePrototype` renders with `showHeader={false}`, `HomeCarousel`'s own `SiteHeader`/`MobileNavPanel` is the sole surviving instance, kept visible at ≤767px by `index.astro`'s CSS overrides. No duplicate dialog IDs.
- HOME-14/HOME-15: `MobileHomePrototype` fully owns the phone-width journey (wordmark → description reveal → photo transition); `HomeCarousel`'s scroll-deck correctly stays desktop-only.
- Cross-page header: `SiteHeader.astro`'s changes (both Phase 20's and `6c51695`'s) don't leak into Gallery/Édition/About/Contact — 61 `site-header.spec.ts` assertions across every page type and three breakpoints all pass.

**Broken:**
- HOME-16: `pickRandomGalleryIndex()` (`HomeCarousel.astro:1725`) still runs and writes `--current-accent`/`--current-accent-text` onto `.home` — but `.home`'s non-header children are `display: none !important` at phone width, and the real phone-visible background is a completely separate mechanism: `phoneCanvasColor={galleries[0]?.heroColor}` (`index.astro:70`, hardcoded to the first gallery), applied via `BaseLayout.astro:188`'s own inline `html, body` style. The two mechanisms never talk to each other. `MobileHomePrototype.astro` has no randomization logic at all (confirmed by grep, zero matches).
- **Verification method:** the integration checker loaded `/` at 390×844 with `Math.random` forced to `0`, `0.5`, and `0.999` across three separate page loads and found `document.body`'s computed background color identical every time. The orchestrator independently re-confirmed the structural claim by reading `index.astro:70`, `BaseLayout.astro:188`, and grepping `MobileHomePrototype.astro` directly — the safety classifier was unavailable for that subagent run, so this claim was not accepted on the subagent's word alone.
- **Why the existing suite didn't catch it:** `homepage-accent-random.spec.ts` forces a `1280×800` desktop viewport in its own `beforeEach` and reads `--current-accent` via `getComputedStyle`, which returns a value regardless of whether the element carrying it is actually visible. The test has never exercised the phone-width code path this requirement targets.
