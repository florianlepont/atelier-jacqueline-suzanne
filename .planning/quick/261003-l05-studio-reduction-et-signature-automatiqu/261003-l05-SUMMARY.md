# Quick 261003-l05: Studio image reduction and automatic signature Summary

## Honest risks

1. End-to-end behaviour unverified (see above).
2. `AssetSource.Uploader` is marked beta in `@sanity/types`; `sanity` is pinned to 6.6.0 with `autoUpdates: false`, but any future `sanity` bump requires re-running the manual checks (documented).
3. Canvas re-encoding converts to sRGB and drops the ICC profile (the offline script keeps it); Safari cannot encode WebP through canvas (the wrapper falls back to the original with a warning). Both are documented.

## Design discretions taken

- Longest side, not width (the offline script caps width only; the doc states the difference with the 4000x6000 example).
- Interception through the global `form.image.assetSources` resolver, wrapping the default source's Uploader by composition and keeping its `name` (`sanity-default`), `component`, `icon` and other properties; no second source (which would trigger an upload-destination picker), no schema edit.
- Quality 0.9; PNG stays PNG, WebP stays WebP; a MIME-type mismatch from the encoder is treated as a failure (original uploaded with a warning).
- Re-encode whenever the signature is on (EXIF/GPS stripped); with the signature off an already-small image is untouched.
- Serial queue + 30 s timeout + 100 MiB input guard + abort support; notices batched (flush on queue idle, 6 s maximum wait).
- Output file naming keeps a matching alias extension (`photo.jpeg` stays), replaces a known image extension that does not match, and appends otherwise (`my.photo` becomes `my.photo.webp`); an empty or extension-only name becomes `image.<ext>`.
- Several fallback names in one toast are joined with " ; " and followed by " et N autre(s)." when more than three.
- The notice of a run that was aborted mid-processing is dropped (nothing is uploaded).
- No new dependency; test placement at root for `.ts` and in the Studio for the `.tsx`.
