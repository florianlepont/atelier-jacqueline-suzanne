<objective>
Fix a regression in the just-deployed quick-260727-drq fix: `.is-tracking` (which disables the peek transform's CSS transition so the live mousemove-driven push is instant, killing Safari's per-mousemove transition-retarget jitter) is armed exactly once per hover session on `mouseenter`, but `commitEdge()` removes it before its full-slide commit and never re-adds it. Root cause is confirmed live and precisely located — DO NOT re-diagnose. `finish()` (the single-shot completion handler inside `commitEdge()`, ~line 980) resets `committing = false`, removes `.is-opening`, and restarts auto-advance, but never re-arms `.is-tracking`.

Purpose: restore Bug 1's invariant for the 2nd-and-later peek in a hover session, not just the first.
Output: a guarded re-arm of `.is-tracking` in `finish()`, plus an FR+EN e2e regression test reproducing the exact multi-peek sequence.
</objective>
