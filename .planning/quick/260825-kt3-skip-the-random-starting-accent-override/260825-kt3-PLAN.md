<objective>
Fix a live bug in the homepage's return-navigation continuity: opening a gallery from the homepage carousel and then using the detail page's scroll-up-to-return gesture lands the visitor back at `/?carousel=<slug>`, where the CORRECT gallery is re-shown (photo, title, index label, progress dash) but its accent COLOUR has changed to an unrelated one — breaking the visual continuity between the detail page just left and the homepage returned to.

Cause (already fully investigated — do not re-diagnose): in `src/client/home-carousel-runtime.ts`, the HOME-16/D-05 "random-per-visit STARTING accent" block at lines 1155-1173 runs UNCONDITIONALLY at mount, immediately after `render()`. It picks a genuinely random gallery index and overwrites `--current-accent`/`--current-accent-text`/`accentPanel.style.color` with THAT gallery's accent — discarding the correct values `render()` had just set for `galleries[carouselIndex]`. The block's own comment already acknowledges that `carouselIndex` may be "gallery 0, or the `?carousel=<slug>` target above", but the code never branches on which case it is.

Purpose: the random starting accent is a FRESH-LANDING affordance. A return navigation is not a fresh landing — it must preserve the colour identity of the gallery being returned to.
Output: one boolean flag plus one conditional wrap around the existing block, and the regression case whose absence let this ship.
</objective>
