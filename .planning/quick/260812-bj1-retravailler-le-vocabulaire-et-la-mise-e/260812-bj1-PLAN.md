```
export interface ReleasePipelineDisplaySegments {
  testSite: PipelineSegmentKind
  liveSite: PipelineSegmentKind
}

export function pipelineDisplaySegments(segments: ReleasePipelineSegments): ReleasePipelineDisplaySegments
```

Merge precedence for `testSite`, evaluated in this order against `segments.content` and `segments.staging`: if either is `'failed'` → `'failed'`; else if either is `'active'` → `'active'`; else if both are `'done'` → `'done'`; else `'pending'`. `liveSite` is `segments.production` verbatim. The function takes no other input, reads no module state, and is a pure projection — it must not re-derive anything from `DeploymentState`.

Add a short head comment above it recording the two facts a future reader needs: (1) this is the only place the underlying three pipeline stages collapse into the two the maintainer sees, and (2) the merged segment can only reach `'failed'` via the site-de-test deploy, because `releasePipelineState` never assigns `'failed'` to `segments.content` — which is why the action row below the bar can still name which stage broke even though the bar no longer separates them (this closes the CONTEXT discretion item about failure distinguishability).
