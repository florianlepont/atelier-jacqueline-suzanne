  <files>playwright.config.ts, tests/e2e/helpers/content.ts, tests/e2e/seo.spec.ts, tests/e2e/critical.smoke.spec.ts, tests/e2e/site-header.spec.ts, tests/e2e/page-title-header-bleed.spec.ts, tests/e2e/accessibility.spec.ts, tests/e2e/edition.spec.ts</files>
  <action>
First, make local verification targetable. In `playwright.config.ts` introduce two module-level constants read from `process.env.E2E_PORT` and `process.env.E2E_BASE_URL`, defaulting to `4321` and `http://localhost:${port}` respectively. Use them for `use.baseURL`, `webServer.url`, and pass the port through to the preview command. Behaviour with neither variable set MUST be byte-for-byte equivalent to today (astro preview already defaults to 4321) — CI sets neither. Change nothing else in the config.

Then create `tests/e2e/helpers/content.ts`, a non-spec module inside `testDir` (Playwright's default `testMatch` only collects `*.spec.ts`, so it will not be picked up as a test file). Export async functions that derive real content routes from the site's own rendered output:
  - `galleryHrefs(page, locale)` — returns every gallery detail href for the requested locale
  - `firstGalleryHref(page, locale)` — convenience wrapper, throws a descriptive error if none exist
  - `editionHrefs(page, locale)` / `firstEditionHref(page, locale)` — same for éditions

Derive via `page.request.get()` against the listing page (`/` or `/en/` for galleries; `/editions/` or `/en/editions/` for éditions) and extract anchor targets from the returned HTML, rather than via `page.goto` + locators. Three reasons, all of which must hold in the implementation: (1) it has no side effect on the caller's page state, so a helper call can sit mid-test; (2) it does not depend on which homepage runtime mounted, so it works under both the `chromium` and the `webkit-mobile` Playwright projects — `critical.smoke.spec.ts` runs under both; (3) it does not require toggling the homepage into grid mode first. Match on the trailing `<segment>/<slug>/` shape so an `ASTRO_BASE` prefix such as `/ajs-website/` is preserved intact in the returned href, and filter by locale so a French call never returns an `/en/` route. Dedupe results and preserve document order. Return the hrefs exactly as they appear in the markup so callers can hand them straight to `page.goto`.

Now retarget every Class A site listed in `<audit_findings>` to call the helper. For the two module-level `for (const path of [...])` loops in `site-header.spec.ts`, the gallery entry cannot stay in a statically-evaluated array: extract the loop body into a local async function taking a path, keep the static routes in the array loop, and add one additional `test(...)` that derives the gallery href inside the test body and calls the same function. Apply the same restructuring to the static path array in `accessibility.spec.ts` — drop the gallery route from the array and add a derived-slug gallery test that mirrors the derived-slug édition test already present further down that file. In `seo.spec.ts`, `critical.smoke.spec.ts`, `page-title-header-bleed.spec.ts`, and `edition.spec.ts` the literals sit inside test bodies, so derive at the top of the test and use the result for both navigation and any URL-shape assertion — assertions that today compare against a fixed slug must compare against the derived one.

Do not describe the removed slug values in the comments you write; refer to them conceptually ("the first published gallery"). Preserve every existing behavioural assertion — this task changes only how a page is reached, never what is checked once there.

Finally, sweep the remaining e2e specs for any Class A site the inventory missed and fix it the same way. Do not open or modify `homepage-wordmark-peek.spec.ts` or `homepage-accent-random.spec.ts`.

Run `npm run build` before any Playwright invocation so `dist/` contains current Sanity content. If `lsof -ti tcp:4321` shows a listener, check `ps` for it: if it is an unrelated long-running `astro dev`, leave it running and verify with `E2E_PORT=4331` instead — do not kill it, it may belong to a concurrent session.
  </action>
