### Final subtitle wording chosen for each of the eight states

1. `requestError` truthy → « La publication sur le site en ligne n'a pas pu démarrer. »
2. `segments.production === 'active'` → « Publication sur le site en ligne en cours… »
3. `segments.production === 'failed'` → « Échec de la publication sur le site en ligne — réessayez. »
4. `segments.staging === 'failed'` → « Échec de la mise à jour du site de test. »
5. `segments.content !== 'done'`, `modifiedCount === 0` → « Aucune modification publique en attente. »
   `segments.content !== 'done'`, `modifiedCount > 0` → « N contenu(s) modifié(s) depuis la dernière mise en ligne. » (+ » Rien n'a été lancé pour l'instant : cliquez sur « Mettre le site à jour » pour démarrer. » when `notStarted` is also true)
6. `segments.staging !== 'done'` → « Mise à jour du site de test en cours… »
7. `segments.production !== 'done'` (staging/content both done) → « Site de test à jour — prêt à publier sur le site en ligne. »
8. fallback (all done) → « Aucune modification publique en attente. »

### Coupling bug found during scoping and fixed here

Emptying the promote copy would have silently deleted the production-release button, because the button was nested inside a box whose existence was derived from that copy (`Boolean(title || detail || actionUrl)`, which collapses to `Boolean(actionUrl)` — false in the ready state — the instant the copy disappears). `tests/unit/release-gate.test.ts` had already documented the coupling in a failure message before this plan; it is now inverted to assert the opposite contract (no copy, button still enabled), with reachability guarded structurally via `gateVariant === 'ready' || actionUrl` and asserted in `tests/unit/editorial-dashboard-markup.test.ts`.

### Lifted restriction

The immediately-preceding quick task (260812-q0d) pinned the panel header subtitle JSX as untouchable and locked an existing markup test to its exact contents. That restriction was deliberately lifted for this task's Task 3 — changing the subtitle was the entire point of this plan.

### requestError now absent from the UI

The raw `requestError` string is no longer displayed anywhere in the dashboard — a deliberate consequence of the no-text-in-the-box instruction, not an oversight. Retry for that state stays reachable through the round gate button, since `gateClickAction('failed')` routes it to a release retry.
