## API vérifiée pendant la planification — ne pas re-deviner

L'outil MCP `context7` n'était pas disponible dans cette session, ni la CLI `ctx7`. La source la plus fiable et la plus exacte en version a donc été consultée directement : **les déclarations TypeScript embarquées dans le paquet `sanity@6.6.0` installé** (`sanity/node_modules/sanity/lib/_chunks-dts/ActiveWorkspaceMatcherContext.d.ts`). C'est plus autoritatif que la documentation web, qui n'est pas versionnée par release.

Faits établis (versions installées : `sanity` 6.6.0, `@sanity/ui` 3.5.0, `react` 19.2.7) :

1. **Le point de personnalisation existe et est le bon.**
   `ArrayDefinition.components?: ArrayOfObjectsComponents | ArrayOfPrimitivesComponents` (ligne ~13391), et
   `ArrayOfObjectsComponents.item?: ComponentType<ObjectItemProps>` (ligne ~13145).
   → `components: {item: PrimaryPhotoItem}` se pose sur la définition du champ **tableau**, avec la signature `ComponentType<ObjectItemProps>` (le générique par défaut, PAS `ObjectItemProps<ImageValue & ObjectItem>`).

2. **`props.index` est fourni directement — la position est triviale à obtenir.**
   `BaseItemProps<T>` (ligne ~12209) expose `index: number` (« The index of the item »), et `ObjectItemProps extends BaseItemProps<Item>` (ligne ~12259).
   → **Le premier élément est simplement `props.index === 0`.**
   → **N'implémente PAS** la piste spéculative évoquée dans la demande initiale (dériver le chemin du tableau parent en tranchant `props.path`, appeler `useFormValue`, comparer les `_key`). C'est inutile ici et bien plus fragile. `props.index` suffit.

3. **`renderDefault` est sur les props.**
   `renderDefault: (props: ItemProps) => React.JSX.Element` sur `BaseItemProps`.
   → `props.renderDefault(props)` rend l'élément par défaut complet (vignette, poignée de déplacement, menu « … »). Ne réimplémente rien de tout cela.

4. **`ObjectItemProps` est exporté depuis `'sanity'`** (présent dans la table d'export de `lib/index.d.ts`). `import {type ObjectItemProps} from 'sanity'` fonctionne.

5. **Mise en garde de stabilité :** `ArrayDefinition.components` et `ArrayOfObjectsComponents` portent tous deux les annotations `@hidden @beta` dans les typings de la 6.6.0. L'API type-checke et est la voie officielle de personnalisation, mais elle est marquée beta en amont — à mentionner dans le SUMMARY.

6. **Composants disponibles pour le badge :** `@sanity/ui` 3.5.0 est déjà utilisé partout dans ce Studio (`Badge`, `Box`, `Card`, `Flex`, `Text` importés dans `EditorialDashboard.tsx`, `MediaLibrary.tsx`, `PublishedPageLinks.tsx`). `<Badge fontSize={0} …>` est déjà le primitif établi de ce codebase — l'utiliser plutôt que du CSS ad hoc.

La seule inconnue non résolvable statiquement est de savoir si l'entrée tableau en mode **grille** honore bien `components.item` (l'entrée en mode liste le fait à coup sûr). C'est exactement ce que la vérification en direct de la Tâche 3 doit trancher, et c'est pourquoi cette tâche est un point de contrôle bloquant.
