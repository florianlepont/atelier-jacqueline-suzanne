# Phase quick-260812-p85 Plan 1: Split the production release gate into preview + publish Summary

Split the single-click round gate control (which previewed and published to production on the same click) into two deliberate steps: the ▶ control now only opens the site de test and records that the current batch was previewed; a new, separately-labelled "Publier sur le site en ligne" button — disabled until that preview happens — is the only control that starts a real production release.

## What Was Built

**`sanity/editorial/releaseGate.ts`** — a new, dependency-free module (zero imports) exporting the three pure rules governing the gate:

- `gateClickAction(variant)` — routes `ready` to `preview`, `failed` to `release` (a retry needs no fresh preview), and everything else to `inert`.
- `nextPreviewedFlag(variant, current)` — preserves the preview flag only while `ready`; clears it for `locked`, `active`, `done` and `failed`.
- `productionPublishDisabled({promoteButtonDisabled, hasPreviewedStaging})` — `promoteButtonDisabled || !hasPreviewedStaging`, with a named-object parameter so the two booleans can't be swapped silently.

**`sanity/editorial/EditorialDashboard.tsx`** rewired around it:

- The round gate control's `onClick` now calls a new `handleGateClick`, which branches on `gateClickAction(gateVariant)`: on `preview` it opens `SITE_PREVIEW_URL` in a new tab (`window.open(..., '_blank', 'noopener')`) and sets `hasPreviewedStaging` true; on `release` it calls the existing `triggerProductionReleaseClick()`; on `inert` it does nothing. The release trigger is no longer reachable from the `ready` branch.
- `title`/`aria-label` on the gate button now show a derived `gateLabel` — "Ouvrir le site de test" for the preview action, falling back to `pipeline.promote.buttonLabel` unchanged for every other variant (including `failed`'s retry).
- A `useEffect` keyed solely on `gateVariant` resets `hasPreviewedStaging` via `nextPreviewedFlag(gateVariant, current)` on every transition — this is the invariant that stops a stale approval of one batch unlocking a newer, unreviewed one.
- A new `Button` ("Publier sur le site en ligne") renders inside the existing `.editorial-dashboard__pipeline-detail` box only when `gateVariant === 'ready'`, disabled via `productionPublishDisabled({promoteButtonDisabled: pipeline.promote.buttonDisabled, hasPreviewedStaging})`, `loading={releaseBusy}`, and `onClick={() => void triggerProductionReleaseClick()}`.
- The private `type PipelineGateVariant` declaration was removed in favour of the one now imported from `releaseGate.ts`.

**Tests:**

- `tests/unit/release-gate.test.ts` — full behavioural coverage of all three pure functions across all five gate variants, all four `productionPublishDisabled` input combinations, plus a coupling test against `releasePipelineState()`'s `ready` branch proving the promote row still carries non-empty title/detail copy (so the pipeline-detail box, and therefore the new button, has somewhere to render).
- `tests/unit/editorial-dashboard-markup.test.ts` — a new sixth `describe` block guarding the JSX/hook wiring the pure functions can't reach from `node`: the gate button never references the release trigger directly, it routes through `gateClickAction(gateVariant`, the preview open and the flag-set-to-true happen together, the reset effect is a `useEffect` keyed solely on `[gateVariant]` routed through `nextPreviewedFlag(gateVariant`, and the publish button is gated on `productionPublishDisabled(` with its label appearing exactly once.
