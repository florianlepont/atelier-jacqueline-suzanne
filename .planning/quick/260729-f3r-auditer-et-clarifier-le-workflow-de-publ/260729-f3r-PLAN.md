<objective>
Faire du tableau de bord Sanity l'unique point de mise en ligne : conserver l'auto-enregistrement en brouillon, rendre visibles et vérifiables les modifications publiques, publier le lot prêt de manière atomique, puis suivre honnêtement le déploiement GitHub Pages.

Purpose: Donner à l'éditrice un modèle mental unique et sûr sans Content Releases payantes, sans nouveau secret et sans toucher au rendu public.
Output: Un registre public canonique, un préflight exhaustif, une transaction Actions API, une carte de publication avec confirmation et récupération d'erreur, une machine d'état temporelle GitHub, des tests et un guide éditorial à jour. La branche est localement livrable; le rôle éditeur et le webhook live restent une UAT manuelle séparément autorisée.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Studio navigateur → Content Lake | Un compte Studio authentifié envoie un lot de publication; Content Lake reste l'autorité de permission et d'atomicité. |
| Données draft → préflight client | Des documents incomplets, obsolètes ou liés à une cible absente ne doivent pas atteindre l'Actions API. |
| Studio navigateur → GitHub REST public | Le Studio lit des métadonnées publiques de runs sans transmettre de secret. |
| Webhook Sanity → GitHub Actions | Le déclenchement et son fan-out sont externes au dépôt et doivent être observés manuellement. |
