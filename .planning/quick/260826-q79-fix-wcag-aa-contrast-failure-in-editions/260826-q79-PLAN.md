## Which pairings are actually real (answers the open question in the deferred-items writeup)

`EditionsOverviewBody.astro`'s `<script>` sets `--editions-row-accent` (background) and `--editions-row-accent-text` on `<html>` from the HOVERED row's palette entry. `:global(html.editions-row-active) .editions-index__row { color: var(--editions-row-accent-text) }` applies that same text colour to **every** row, dimmed or not. So a dimmed title is always `text[i]` over `bg[i]` for the same index `i`. There are exactly **five** pairings, not ten:

| i | accent bg token | resolves to | paired text token | resolves to | contrast @0.28 | min alpha for 3:1 | contrast @0.75 |
|---|-----------------|-------------|-------------------|-------------|----------------|-------------------|----------------|
| 0 | `var(--color-accent)` -> `--pink-600` | `#D6327C` | `var(--color-on-accent)` -> `--gray-0` | `#FFFFFF` | 1.49:1 | **0.717** | **3.16:1** |
| 1 | `var(--palette-purple)` | `#A73AF4` | literal | `#FFFFFF` | 1.52:1 | 0.703 | 3.23:1 |
| 2 | `var(--palette-teal)` | `#55FFE1` | `var(--color-ink)` -> `--gray-900` | `#1A1A1A` | 1.81:1 | 0.478 | 6.89:1 |
| 3 | `var(--palette-lime)` | `#A6FD29` | `var(--color-ink)` | `#1A1A1A` | 1.81:1 | 0.479 | 6.81:1 |
| 4 | `var(--palette-plum)` | `#37013A` | literal | `#FFFFFF` | 2.32:1 | 0.354 | 9.80:1 |

Both an ink-paired case (teal, lime) and a white-paired case (pink, purple, plum) are real. Note the deferred-items writeup's "ink `#1A1A1A` over `#D6327C`" figure is now **stale history**: quick-260825-g2l repointed `--color-on-accent` from `--gray-900` to `--gray-0`, so the live entry-0 pairing is white-on-pink, not ink-on-pink.

**Worst case is entry 0 (white on `#D6327C`), needing alpha >= 0.717.** The chosen shipped value is **`0.75`** — the nearest clean quarter-step above the worst-case floor, landing at 3.16:1 (~5% headroom over the 3:1 threshold, enough to absorb 8-bit compositor rounding and axe's own blend arithmetic) while keeping the dim as strong as the constraint permits. `0.72` clears by only 0.8% and is too tight; anything higher than `0.75` weakens the visual effect for no accessibility gain.

Threshold is **3:1, not 4.5:1**: the title is `font-family: var(--font-display)` at `clamp(32px, 5vw, 64px)` with `--weight-semibold`, and the rule is desktop-only (>800px, where `5vw` >= 40px), so it is unambiguously WCAG large text. 4.5:1 is mathematically unreachable here anyway — entry 0 would need alpha 0.991, i.e. no dimming at all.

## Contrast math the unit test must implement

sRGB relative luminance per WCAG 2.x; alpha compositing happens in gamma space (which is what CSS `opacity` does), so blend the 8-bit channels directly and round:

- `blend(t, b, a)[c] = Math.round(a * t[c] + (1 - a) * b[c])`
- `lin(c) = c/255 <= 0.04045 ? (c/255)/12.92 : (((c/255)+0.055)/1.055) ** 2.4`
- `L = 0.2126*lin(r) + 0.7152*lin(g) + 0.0722*lin(b)`
- `contrast = (Lhi + 0.05) / (Llo + 0.05)`

`getHeroTextColor` in `src/lib/site-config.ts` already carries the same luminance formula — mirror its constants exactly rather than inventing new ones.
