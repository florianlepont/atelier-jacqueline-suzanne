# Phase 24 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Design status for this phase:** unusually pre-resolved. D-08/D-09 in `24-CONTEXT.md` lock the CTA's visual treatment via sketch `.planning/sketches/018-gallery-edition-contact-cta/` (winner: Variant B "Renforcé", confirmed by Florian). This document translates that locked decision — plus the codebase's own existing `.edition-detail__related` precedent (which EDN-12 must mirror per D-01/D-03) — into the formal contract. It does not reopen any visual decision already made.

**Correction vs. the sketch's placeholder markup:** the sketch's `.related-link` class (used to represent "the existing related-gallery link" in its comparison frames) is a simplified stand-in. The REAL, currently-shipped `.edition-detail__related` treatment (read directly from `src/components/EditionDetailBody.astro`) is a bordered/framed link — 2px `currentColor` border, `10px var(--space-md)` padding, `44px` min-height, arrow via `::after` — not a plain underlined text link. Per D-01 ("mirror the existing forward pattern exactly") and D-09 ("its current subtle treatment stays exactly as-is"), EDN-12's new `.gallery-detail__related` must copy this REAL bordered treatment byte-for-byte (renamed only), not the sketch's simplified placeholder. This does not affect CONT-04 — Variant B's CTA markup/CSS is sketched and confirmed directly against real theme tokens and is accurate as-is.

## Component Contract: Reverse Cross-Link (EDN-12)

**New class:** `.gallery-detail__related` in `src/components/GalleryDetailBody.astro`, positioned identically to `.edition-detail__related` — immediately inside `.gallery-detail__content`, before the `GalleryGrid` render, only when `relatedLink` is non-null (per D-02/D-03).

**CSS — copy `.edition-detail__related` verbatim, renamed only** (verified current source, `src/components/EditionDetailBody.astro`):

```css
.gallery-detail__related {
  display: inline-flex;
  align-items: center;
  gap: var(--space-sm);
  min-height: 44px;
  padding: 10px var(--space-md);
  font-size: var(--text-label-size);
  font-weight: var(--weight-semibold);
  line-height: 1.2;
  color: var(--color-ink);
  text-decoration: none;
  white-space: nowrap;
  border: 2px solid currentColor;
  margin: 0 0 var(--space-2xl);
}

.gallery-detail__related::after {
  content: '→';
  flex: none;
  font-size: 20px;
  line-height: 1;
}

.gallery-detail__related:hover,
.gallery-detail__related:focus-visible {
  color: var(--color-accent);
  outline: 2px solid var(--color-accent);
  outline-offset: var(--focus-ring-offset);
}

@media (max-width: 767px) {
  .gallery-detail__related {
    max-width: 100%;
    margin: 0 0 var(--space-xl);
  }
}
```

**States:**
- **Default:** `var(--color-ink)` text/border, no accent.
- **Hover:** text + outline swap to `var(--color-accent)` (pink); no layout shift, no `translateX` (this element does not use the CONT-04 arrow-slide interaction — that motion is exclusive to Variant B's CTA per the sketch, do not cross-apply it here).
- **Focus-visible:** identical treatment to hover (combined selector, matching the existing precedent exactly).
- **Absent (no `relatedEdition`):** element does not render — verify with `{relatedLink && (...)}` conditional, mirroring `EditionDetailBody.astro`'s existing `{relatedLink && (...)}` pattern exactly.

**Responsive behavior:** identical box treatment at both breakpoints; only the bottom margin changes (`--space-2xl` desktop/tablet ≥768px → `--space-xl` mobile ≤767px), matching the existing `.edition-detail__related` breakpoint behavior exactly.

## Component Contract: Contact CTA (CONT-04)

**New classes**, one scoped set per detail body (Astro scopes `<style>` blocks per-component automatically, so identical inner class names in `GalleryDetailBody.astro` and `EditionDetailBody.astro` do not collide — no shared-component extraction is required or recommended; this matches the existing pattern where both bodies already independently declare their own `__content` padding rules rather than sharing a base style module):

- `.gallery-detail__contact-cta-zone` / `.edition-detail__contact-cta-zone` (outer wrapper)
- `.gallery-detail__contact-cta-rule` / `.edition-detail__contact-cta-rule` (hairline rule)
- `.gallery-detail__contact-cta` / `.edition-detail__contact-cta` (the `<a>`)
- `.gallery-detail__contact-cta-arrow` / `.edition-detail__contact-cta-arrow` (the arrow `<span>`)

**Placement:** immediately after the `GalleryGrid` render, still inside `.gallery-detail__content` / `.edition-detail__content`, as the last element before that div closes (D-07). Renders unconditionally on every gallery and every édition — no conditional logic, no sold/empty-state variant (per CONTEXT.md's "Applies universally... no conditional/sold-state logic").

**Markup (sketch 018 Variant B, verbatim structure — real class names substituted, and the sketch's hardcoded mobile `<br>` line-break removed per the sketch's own inline comment: "real implementation should let CSS/text-wrap handle this responsively rather than hardcoding a `<br>`, since real copy width will differ slightly from the sketch's placeholder French string"):**

```html
<div class="gallery-detail__contact-cta-zone">
  <div class="gallery-detail__contact-cta-rule"></div>
  <a class="gallery-detail__contact-cta" href="/contact/">
    Intéressé·e par une pièce ? Contactez-nous
    <span class="gallery-detail__contact-cta-arrow" aria-hidden="true">→</span>
  </a>
</div>
```

(Use `getRelativeLocaleUrl(locale, 'contact')` for the href, not a literal `/contact/` string, per D-04 and this codebase's base-path-safety convention — the literal string above is illustrative only.)

**CSS (sketch 018 Variant B, verbatim values — confirmed against real theme tokens):**

```css
.gallery-detail__contact-cta-zone {
  padding-top: var(--space-2xl);
}

.gallery-detail__contact-cta-rule {
  border-top: 1px solid var(--pink-600);
  width: 48px;
  margin-bottom: var(--space-md);
}

.gallery-detail__contact-cta {
  display: inline-flex;
  align-items: center;
  gap: 10px;
  color: var(--color-ink);
  font-family: var(--font-display);
  font-weight: 600;
  font-size: 20px;
  line-height: 1.25;
  text-decoration: none;
  border-bottom: 1px solid transparent;
}

.gallery-detail__contact-cta-arrow {
  color: var(--pink-600);
  font-size: 20px;
  transition: transform 0.15s ease;
}

.gallery-detail__contact-cta:hover,
.gallery-detail__contact-cta:focus-visible {
  border-bottom-color: var(--color-ink);
}

.gallery-detail__contact-cta:hover .gallery-detail__contact-cta-arrow,
.gallery-detail__contact-cta:focus-visible .gallery-detail__contact-cta-arrow {
  transform: translateX(4px);
}
```

**Gap closed vs. the raw sketch (research-flagged, now resolved in this contract):** the sketch's `.cta--b` had only a `:hover` rule, no `:focus-visible`. This contract adds an explicit combined `:hover, :focus-visible` selector (both for the border-bottom underline reveal and the arrow's `translateX(4px)` shift) so keyboard-focus parity matches `.gallery-detail__related`'s/`.edition-detail__related`'s existing combined-selector convention. The site's global `a:focus-visible { outline: 2px solid var(--color-accent); outline-offset: var(--focus-ring-offset) }` rule (`BaseLayout.astro`) still applies on top of this — do not suppress or override it.

**States:**
- **Default:** ink-colored text, pink arrow, transparent border-bottom (invisible underline placeholder).
- **Hover:** border-bottom reveals in ink color; arrow slides `translateX(4px)`; transition `0.15s ease`.
- **Focus-visible:** identical visual reveal to hover (border-bottom + arrow shift) PLUS the site's standard pink focus-ring outline (inherited global rule, not redefined here).
- **No disabled/loading/error state** — static link, no interactivity beyond navigation.

**Motion note:** `translateX(4px)` over `0.15s ease` is a small, non-decorative micro-interaction (arrow nudge), not a candidate for a `prefers-reduced-motion` guard — consistent with RESEARCH.md's own assessment ("likely not needed for a simple `translateX` hover"). Do not add a reduced-motion media query for this.

## Accessibility Notes (beyond template — carried from RESEARCH.md's Security/ASVS pass and this phase's own review)

- Both new links are real `<a href>` elements — no `role="link"` on a non-anchor, no client-side-only navigation.
- Decorative arrow glyphs are excluded from the accessibility tree (`::after` CSS content on EDN-12's link; `aria-hidden="true"` span on CONT-04's link) — screen readers announce only the link's real text content.
- Tap targets: `.gallery-detail__related` explicitly sets `min-height: 44px` (matches `--tap-target-min`). `.gallery-detail__contact-cta` does not explicitly set a min-height in the sketch-pinned CSS — its `inline-flex` content (20px line-height text + 10px gap) naturally exceeds 44px total clickable height once its padding-top zone (`--space-2xl` = 48px) and surrounding whitespace are accounted for, but the anchor's own hit-box is text-height only. This is accepted as-is because it matches the sketch's confirmed, signed-off design exactly (D-08) — do not add padding to artificially inflate the tap target, as that would visually diverge from the approved sketch. Flag to `gsd-ui-checker`/`gsd-ui-auditor` as an intentional, sketch-confirmed exception, not an oversight.
- Focus order: both new elements are real DOM-order anchors (no `tabindex` manipulation), so keyboard tab order follows visual order automatically — EDN-12's link (top of content, gallery pages only) tabs before the grid; CONT-04's CTA (bottom of content, both page types) tabs after the grid, matching D-03's "opposite end of the page" framing.
