## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user gesture (tap / Escape / resize) -> `<dialog>` top-layer state | The only new boundary this plan opens. No data crosses it; the state machine is entirely client-side UI state with no persistence and no network call. |
| `<dialog>` top layer -> the rest of the document | While open, the panel paints above and makes inert everything outside it. Exiting that state correctly is a availability concern, not a confidentiality one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-03 | Denial of Service | the panel's `transitionend`-gated close funnel | high | mitigate | A `transitionend` that never fires would leave the visitor permanently inside a focus-trapped, viewport-filling modal with every dismiss route already consumed — a self-inflicted lockout on the site's landing page. Four layers: (a) a `window.setTimeout(finishClose, 400)` safety net armed on every animated close; (b) a `closing` re-entrancy flag so rapid taps cannot interleave two close sequences; (c) the `transitionend` handler filtered to `event.target === panel` so the three morphing bars cannot resolve the close early and leave the flag stuck; (d) a `phoneQuery` `change` listener that force-closes when the viewport crosses to >=768px, where the only dismiss control is `display: none`. Verified by Task 3 tests 3, 4, 6 and 7 plus the WebKit smoke test. |
| T-20-09 | Spoofing | hand-rolling focus containment instead of using `showModal()` | medium | mitigate | A bespoke focus-trap could leak focus to background controls that are visually hidden behind the top layer, letting a visitor activate an affordance they cannot see. Mitigated by using `showModal()` exclusively (asserted: zero `keydown` listeners in the component) and by Task 3 test 2, which walks eight Tab presses and asserts focus never leaves `#mobile-nav`. |
