<objective>
Close `21-UAT.md` round-2 gap 1 (`.planning/debug/homepage-scroll-intro-logo-duplication.md`): replace plan 21-10's two stacked full-viewport intro sections — each rendering its own separate logomark image at matched static geometry — with ONE pinned, scroll-scrubbed intro block containing exactly one logomark that shrinks continuously as the tagline arrives beneath it.

Purpose: this corrects assumption A4, not a defect. The shipped code implements A4 exactly as written: two independent, ordinary-flow sections, two separate `<img>` elements, continuity faked through matched CSS, zero scroll-driven transform on the logo anywhere. The developer's real-device correction is a different mental model — "le logo se réduise et laisse apparaître le texte de présentation": one element, one continuous transformation. The debug session confirms this is not a novel ask relative to this codebase: the wordmark zoom (`computeZoomProgress` + `computeWordmarkZoomState` driving one `.home-scroll-deck__wordmark` inside a sticky stage in a tall track) and `DetailHero.astro`'s `.detail-hero__pin` (one photo lerped by one `t`, with dependent content revealed from sub-ranges of that same `t`) are two existing in-repo instances of exactly this idiom. A4 opted out of it deliberately, to avoid adding a second pinned handoff boundary right before the zoom's own — the defect class plan 21-07 had just fixed. This plan opts back in, and pays that price explicitly by applying plan 21-07's own rigor to the new boundary: live rects every painted frame, no scroll events, no observers.

Two secondary effects are deliberate and load-bearing, not side quests:

1. **It structurally closes half of `21-UAT.md` round-2 gap 2.** The debug session for gap 2 names the intro tagline's failure mechanism precisely: the beats carry no snap point (A3), so a normal-paced flick carries straight through, and the tagline's `is-revealed` class only transits the 0.98 threshold for an instant. A pinned stage removes that mechanism entirely — the tagline is written by scroll POSITION inside a stage that does not move for the whole reveal distance, so it is on screen and fully opaque for the last ~40% of the scrub no matter how the visitor's momentum behaves. Plan 21-15 closes the other half (the gallery slide descriptions, which keep the threshold mechanism).
2. **It changes what the header competes with.** The new logomark ends the scrub at roughly 45% of its starting size — much closer to the small header logomark's own size than the old static beats ever were. Plan 21-14 owns the resulting composition decision together with gap 5's header fix, which is why the two are adjacent waves and not one plan.

Output: three new pure exports plus unit tests, the restructured intro markup and CSS, and the driver extension — all in `src/lib/home-carousel.ts`, `tests/unit/home-carousel.test.ts` and `src/components/HomeCarousel.astro`.

<geometry_note>
## The arithmetic this plan introduces, stated once

Let `V` be the deck viewport height (`var(--deck-vh, 100svh)`, plan 21-11) and `Di` the intro reveal distance.

**Today (A4):** two ordinary-flow sections, each of height `V`. Pre-zoom distance is exactly `2V`. Nothing about the intro is scroll-driven; the logo is static in both.

**After this plan:** one track of height `V + Di` containing a `position: sticky; top: 0` stage of height `V`. The stage pins as soon as the track's top reaches the viewport top (scroll position 0, since the track is the deck's first child) and releases when the track's bottom reaches the stage's bottom, i.e. at `introTrackTop = -Di` — exactly where `computeIntroProgress` reaches 1. Pre-zoom distance becomes `V + Di`.

**What does NOT change:** the zoom's own math. `computeZoomProgress` reads the ZOOM track's own live `getBoundingClientRect().top`, so it is indifferent to what precedes it in the document — exactly the property plan 21-10 already relied on when it prepended two sections. `ZOOM_REVEAL_DISTANCE`, the zoom track's height calc, the stage's sticky release and plan 21-12's slides pull-up are all untouched by this plan.

**The invariant this plan inherits:** the track's height term and the stage's height term must be the SAME expression. If they ever diverge, the sticky release stops coinciding with progress reaching 1, which is the desynchronised-handoff class of bug plan 21-07 eliminated and plan 21-11's own comment already warns about for the zoom track. Change both together, never one alone.

**The new boundary:** the intro track's bottom edge IS the zoom track's top edge (adjacent siblings, no margins). So the instant intro progress reaches 1 and the intro stage releases, zoom progress leaves 0. Both are re-read from live rects in the same painted frame, in document order, which is what keeps the two scrubs from ever disagreeing within a frame.
</geometry_note>
