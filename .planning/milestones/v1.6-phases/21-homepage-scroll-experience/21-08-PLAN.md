<objective>
Close UAT gap 3 (blur-placeholder pop-in / jank on the deck slides): give every `.home-slide` the site's own established HOME-09 blur-up treatment, and give the upcoming slide's photo a real head start.

Purpose: `21-UAT.md`'s third gap has a confirmed root cause — `.home-slide__img` (plan 21-04) is a SINGLE `loading="lazy"` image bound straight to the full-resolution `gallery.heroSrc`/`heroSrcSet` for every slide after the first, with no placeholder layer and no priority hint for the next slide. `.home-hero` and `.home-grid`, one block over in the same component, both already solve exactly this loading-latency gap with a two-image stack: a genuine 24px-wide blurred `gallery.blurSrc` placeholder painting immediately, and the sharp lazy image crossfading over it on load. Plan 21-04 never rendered `blurSrc` into the deck markup even though it is already fetched, already typed on `GalleryEntry`, and already piped into the hidden data node. So on a real phone the grainy frames the recording captured were the real full-resolution photo still arriving over the network with nothing masking the wait — architecturally there is no placeholder for slides at all.

This plan is therefore an application of an existing, shipped, already-approved pattern to a block that was skipped, plus the "consider a preload/priority hint for the upcoming slide" item the same gap lists. It invents no new visual language: the crossfade duration, easing and class name are reused verbatim from `.home-grid__tile-img--sharp`.

D-06 (accent band), D-07 (one photo per gallery) and D-10 (each slide is a real anchor) are untouched — the slide gains a sibling image inside the same anchor, nothing else about its structure changes. D-15 is respected by putting the load-listener wiring in the un-gated carousel script, so a reduced-motion visitor gets the same progressive loading rather than being excluded from it.

Deliberately NOT in this plan: a non-white paint floor behind the placeholder for the brief window before even the 24px image decodes. That belongs to plan 21-09, which owns the deck's background-colour safety net as part of closing `21-UAT.md` gap 4, and doing it here would mean two plans editing the same declarations.

Output: markup, CSS and one script edit in `src/components/HomeCarousel.astro`, plus new cases in `tests/e2e/homepage-scroll-deck.spec.ts`.
</objective>
