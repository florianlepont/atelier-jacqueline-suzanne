# Phase 21 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** phone-width viewports only (`max-width: 767px`). Every rule below applies inside that media query. Desktop/tablet (`min-width: 768px`) carousel/grid markup, CSS, and JS are explicitly OUT of scope and must remain byte-for-byte unchanged (UI-02, success criterion 5). This UI-SPEC formalizes `21-CONTEXT.md`'s D-01 through D-16 (all locked by the user during `/gsd-discuss-phase`) plus the sketch-validated motion spec from `sketch-findings-ajs-website/references/homepage-motion.md` (sketch 015, confirmed on a real phone 2026-08-04) into the contract format the planner/executor/checker consume. No open design questions remain — this document is transcription + gap-filling from the project's existing "Bold & graphic" brand system, not new decision-making.

## Spacing Scale

Declared values (must be multiples of 4) — these are the project's existing, already-shipped tokens (`--space-*` in `BaseLayout.astro`); this phase introduces no new spacing tokens:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (e.g. title→description gap in an arrival-slide's accent panel) |
| md | 16px | Default element spacing |
| lg | 24px | Section padding (mobile accent-panel padding, per existing `.home-hero__accent` mobile override) |
| xl | 32px | Layout gaps (desktop accent-panel padding — not used below 768px) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- `--tap-target-min: 44px` — every tappable element in the new scroll deck (the tap-to-open photo target, D-10) must clear this existing minimum, matching the project's established touch-target floor. Not a new exception, just a reminder this phase's new tap surface must honor it.
- The wordmark zoom's scroll TRACK distance (`REVEAL_DISTANCE`, 900px, "Cinematic" pace per sketch 015) is a **motion/scroll parameter, not a spacing token** — it governs how much page scroll the zoom consumes, not a visual gap between elements. See Motion & Interaction Contract below. Do not confuse it with the `3xl` spacing token despite the coincidental round number.

Component-level mapping (exact reuse of existing shipped values — no new type styles invented):

Reuse `.home-grid__tile-title`'s exact CSS verbatim (`src/components/HomeCarousel.astro` ~line 2758): 2-line clamp (`-webkit-line-clamp: 2`, `min-height: calc(1.2em * 2)`), color `var(--current-accent-text, var(--color-on-accent))`. Always visible (not part of the D-13/D-14 reveal — only the description reveals).
- **Arrival-slide description** (D-06/D-13) → Label role, 14px/400/1.4. Reuse `.home-grid__tile-description`'s exact CSS verbatim (same file, ~line 2790): 3-line clamp, `max-width: 52ch`, color `var(--current-accent-text, var(--color-on-accent))`. This is the element the D-13/D-14 reveal transition targets (see Motion & Interaction Contract).
- **Homepage intro paragraph** (if repeated on the wordmark's arrival slide — Claude's discretion at plan time, D-16 only forbids repeating the *wordmark*, not necessarily the intro copy) → Body role, 15px/400/1.5, reusing `.home-hero__intro`'s exact CSS verbatim.

No new font sizes, weights, or families are introduced. Total distinct sizes in play: 4 (14, 15, 32, viewport-fill-display) — within the 3-4 size budget.

**Font weight budget — 2 in-scope weights, plus 1 pre-existing sitewide brand constant:**

This phase's own in-scope weight budget is exactly 2 weights: 400 (regular — Label/Body) and 600 (semibold — Heading). Those are the only weights this phase introduces or touches.

The Display role's weight 900 ("black") is NOT part of this phase's 2-weight budget — it is a pre-existing, sitewide brand constant. Unbounded weight 900 is the wordmark's typeface weight across the whole site and has rendered at 900 since prior phases (the existing `.home-hero__wordmark` clamp this phase reuses verbatim, per the Component-level mapping above, already renders at 900 today — this phase does not introduce, change, or add that weight; it inherits it unmodified). Because the wordmark is a fixed, cross-phase brand element rather than new UI vocabulary introduced by this phase's own design decisions, it is exempted from the 2-weight in-scope count. Do not add a third weight anywhere else in this phase's new UI — the scroll-deck's own new elements (arrival-slide title/description, intro paragraph) must stay within 400/600 only.

## Motion & Interaction Contract

This phase is primarily a motion/interaction contract; the section below is the authoritative, sketch-validated (real-phone-tested 2026-08-04) source of truth for the executor. All values are LOCKED per CONTEXT.md D-01–D-16 and `sketch-findings-ajs-website` — do not re-derive or re-tune without a documented reason.

### Breakpoint & motion gates
- Structural gate: `@media (max-width: 767px)` — the new scroll-deck markup exists ONLY below this width; the existing carousel/grid markup is unconditionally hidden below it and unconditionally shown at `min-width: 768px` (pure CSS, no JS markup swap — see `21-RESEARCH.md` Anti-Patterns).
- JS gate: `matchMedia('(max-width: 767px)')` AND `matchMedia('(prefers-reduced-motion: reduce)')`, combined exactly as `DetailHero.astro`'s existing `setup()`/`change`-listener idiom, inverted breakpoint direction. Both media queries re-run `setup()` live on `change` (OS-level reduced-motion toggle mid-session, or viewport resize crossing the breakpoint) — do not check once at load only.

### Wordmark → photo zoom (D-01 through D-04, D-16)
- **Mechanism:** extend the existing photo-cutout wordmark (`background-clip: text` + `background-image: var(--wordmark-photo)`), NOT a new visual device.
- **Pin pattern:** `position: sticky` stage inside a tall scroll track (`height: calc(100dvh + 900px)`), mirroring `DetailHero.astro`'s pinned-shrink driver.
- **Scroll distance ("Cinematic" pace):** `900px` — the sketch-validated winner over "Quick" (420px, rejected as abrupt) and "Balanced" (650px, rejected in favor of the slower one). Treat 900px as the starting value; the pace CATEGORY (Cinematic/slowest) is the locked decision, not the exact pixel count — verify live on a real phone against production's actual header height/first-gallery photo and tune only if needed (per `21-RESEARCH.md` Open Question 1).
- **Easing:** ease-in-cubic (`t * t * t`) — accelerating, not linear. Progress `t` derived from `clamp01(-track.getBoundingClientRect().top / 900)`, real page scroll — never a bounded-div `scrollTop` (that was sketch-only scaffolding).
- **Scale:** `transform: scale(lerp(1, 8.5, easeInCubic(t)))` on the wordmark element.
- **Zoom anchor:** `transform-origin` measured LIVE off the "A" of "Atelier" (wrap it in `<span class="focus-letter">`), computed via `getBoundingClientRect()` on both the wordmark box and the focus-letter span — never a hardcoded percentage. Re-run on load, inside `document.fonts.ready.then(...)`, and on resize/orientationchange (Pitfall 4 — measuring before Unbounded loads produces a visibly wrong anchor).
- **Wordmark fade-out:** `opacity: 1 - clamp01((t - 0.92) / 0.08)` — fades out only in the final 8% of progress.
- **Photo crossfade-in (end-state safety net):** a plain full-bleed photo layer behind/over the wordmark stage crossfades `opacity: clamp01((t - 0.85) / 0.15)` — hides any rasterization artifact at the extreme 8.5× scale. Do not try to make the raw cutout flawless at full scale; rely on this crossfade instead.
- **Reversibility (D-04):** driven directly by live scroll position, not a one-shot animation — scrolling back up must smoothly reverse scale/opacity for free, with no separate "replay" logic.
- **No other UI during the zoom (D-03):** no gallery title, no description, no header chrome visible while `t` is between 0 and ~0.92-1.0. The mobile hamburger-nav header (D-12) is hidden during the zoom and fades in only once the zoom completes.
- **Cutout filter (color contrast against the revealed photo):** reuse the existing `wordmarkPhotoFilter()` heuristic verbatim (`HomeCarousel.astro` line ~96) — do NOT invent a new filter recipe (the sketch's own default of `brightness(0.72) contrast(1.15)` was a placeholder; production must use the shipped, text-color-aware heuristic):
  ```
  wordmarkPhotoFilter(textColor) =
    textColor === '#FFFFFF' ? 'brightness(1.38) contrast(0.92)'
                             : 'brightness(0.65) contrast(1.12)'
  ```
  Single `filter` property only, no additional paint layers (box-shadow/text-stroke/second background) — Safari raster-seam regression risk, already diagnosed once (Pitfall 3).
- **Intro-only (D-16):** once the zoom completes, no subsequent `.arrival-slide` repeats the small wordmark-with-photo-cutout treatment. Regular slides show title + description only.

### Scroll-snap gallery deck (D-05, D-07, D-08)
- One `.arrival-slide` per gallery, `height: 100dvh` (not `100vh` — avoids mobile browser-chrome jump), `scroll-snap-align: start`, `scroll-snap-stop: always` (prevents a fast fling skipping a slide entirely).
- Snap container (`scroll-snap-type: y mandatory`) scoped to START AFTER the zoom track — the zoom track/stage must have NO `scroll-snap-align` and must not be inside the mandatory-snap container's direct children, or the browser will fight D-04's continuous scrub (Pitfall 6).
- One photo per gallery (the gallery's existing hero/cover photo) — not a multi-photo preview.
- After the last gallery's slide, scrolling further reaches the site footer — no loop back to slide 1 (D-08).
- Reduced motion: `scroll-snap-type: none` under `@media (prefers-reduced-motion: reduce)` — forced snapping is itself a motion/disorientation vector independent of the JS-level gate above.

### Description reveal (D-13, D-14)
- **Values (verbatim reuse, no new numbers):** `opacity: 0 → 1`, `transform: translateY(8px) → translateY(0)`, `180ms ease` — copied exactly from `.home-grid__tile-description`'s existing hover-reveal rule (`HomeCarousel.astro` ~lines 2778-2804). Do not tune these numbers for the new context.
- **Trigger:** `IntersectionObserver`, threshold `[0, 0.98, 1]`, toggling a `.is-revealed` class when `intersectionRatio >= 0.98` — NOT `scrollend` (Safari support only landed 26.2/Dec-2025; not safe as a sole signal for a phone-focused feature yet — see `21-RESEARCH.md` Pattern 4). Fires on BOTH directions (not `{ once: true }`) since D-04-style reversibility implies scrolling back up should hide the description again.
- **Arrival semantics:** reveal fires once a slide is fully snapped/settled (arrival-complete), not as soon as it starts entering the viewport — matches the roadmap's "arrives on screen" wording as a deliberate post-snap moment.
- **Title is always visible** — only the description opacity/transform is gated by arrival state.

### Reduced-motion end-state (D-15)
- Gate: `(max-width: 767px) and (prefers-reduced-motion: reduce)`.
- No scroll-linked JS attaches at all (scroll listener + IntersectionObserver both fully detached, not merely skipped) — mirrors `DetailHero.astro`/`AboutPageBody.astro`'s existing convention exactly, inverted breakpoint direction.
- Static end-state: full-screen wordmark renders once, at rest (no zoom), then every `.arrival-slide`'s description is permanently visible (`opacity: 1; transform: none;`) with no reveal transition.

### Tap-to-open + touch-handler fix (D-10, D-11)
- Tapping anywhere on an arrival-slide's photo opens that gallery's detail page directly (matches today's grid-mode tap-to-open) — build this as a NEW, separate, simpler handler scoped to the new `<768px` scroll-deck slides (no progress-dash/autoplay-toggle controls exist there to guard against, per D-16).
- **Do not** conflate this with the CR-01 carryover bug fix: that fix (excluding `.home-hero__caption`/progress-dash from misfiring `openCurrent()`) belongs in the EXISTING carousel's `touchend` handler (`HomeCarousel.astro` lines ~970-1002), applied unconditionally, since that code path stays live for touchscreen tablets ≥768px (success criterion 5). A regression test written only against the new mobile markup would miss the actual tablet bug (Pitfall 1).

### Accent color liveness (D-09)
- `--current-accent`/`--current-accent-text` continue updating live to match each gallery's `heroColor`/`heroTextColor` as its slide arrives during scroll — does NOT stay frozen at Phase 20's per-visit random starting pick for the whole scroll. Reuse the existing `render()`-style custom-property write pattern (`HomeCarousel.astro` ~line 728-730).

## Layout & Structure Contract

- **New, parallel markup** (`.home-scroll-deck` or equivalent), sibling to the existing `.home-hero`/`.home-grid` blocks inside the same `<section class="home">`, shown only via `@media (max-width: 767px) { display: block }` / hidden at `≥768px`. Do NOT branch or conditionally repurpose the existing carousel DOM — it carries controls (progress dashes, autoplay toggle, peek layers, hover cursor) this phase's mobile view explicitly does not want (D-01/D-16).
- **Arrival-slide accent panel geometry:** reuse the MOBILE variant of `.home-hero__accent` (full-width, bottom-anchored band — `left: 0; right: 0; bottom: ...; width: 100%; padding: var(--space-lg)`), NOT the desktop corner-panel geometry (`width: min(700px, 52%)`, absolute-positioned bottom-right). D-06 explicitly wants the existing accent-panel *concept* (solid panel, not a scrim-over-photo), and the mobile band variant is the one already tuned for phone width.
- **Toggle/grid retirement below 768px:** the carousel/grid mode-toggle button (`data-action="toggle-mode"`) and the `.home-grid` subtree get a `(min-width: 768px)`-gated existence check — both must be completely absent/non-interactive below 767px (success criterion 1) while staying exactly as-is at ≥768px.
- **Header behavior (D-12):** the Phase 20 mobile hamburger-nav header (logo top-left, hamburger top-right) is hidden during the full-screen wordmark zoom and fades in once the zoom completes — reuse whatever fade/opacity transition idiom is simplest and consistent with the rest of this contract's `180ms ease`/`300ms ease` timing bands already in use elsewhere on this component (do not invent a third timing value without reason).
