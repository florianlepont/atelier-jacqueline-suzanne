<objective>
Wire arrival-complete detection: reveal each slide's description as it settles (D-13/D-14) and update the live accent colour to that gallery's own hero colour (D-09), inside the same gate the zoom driver already uses.

Purpose: this closes phase success criterion 3 ("each gallery's description text is hidden until that gallery arrives on screen during scroll, then reveals via the sketched-and-approved transition") and the second half of HOME-14. `21-RESEARCH.md` Pattern 4 settles the mechanism: an `IntersectionObserver` at a high threshold, not the newer snap-change events (limited availability) and not `scrollend` (only reached Safari in 26.2, so phones on older iOS would silently get no reveal at all). A full-viewport slide can only reach a near-1.0 intersection ratio once it is actually settled, which is exactly D-14's "arrival-complete" semantics.

Output: an observer added to the deck script in `src/components/HomeCarousel.astro`, plus the closing set of cases in `tests/e2e/homepage-scroll-deck.spec.ts`.

This is the last implementation plan of the phase; its verification section carries the phase-level gate, including the manual real-device pass that cannot be automated.
</objective>

## Trust Boundaries

| build-time hero colours -> CSS custom properties | Slide `data-hero-color` / `data-hero-text-color` values, already rendered into the DOM by plan 21-04, are copied into two custom properties on the page root. ## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-06-A | Tampering | Accent custom-property write from slide data attributes | low | accept | The values originate from Sanity at build time and are already used identically by the existing carousel accent path (`render()`); this plan adds no new source and no new sink. A CSS custom property carrying an unexpected string cannot execute — it can at worst produce an invalid colour that falls back to the declared site token. |
| T-21-06-B | Denial of Service | IntersectionObserver left attached across gate changes | low | mitigate | An observer that is created on every `setup()` run without being disconnected would accumulate one live observer per media-query change, leaking listeners on a device where the user toggles orientation or reduced motion repeatedly. Mitigated by creating it only in the attach branch and disconnecting plus nulling it in the detach branch, inside the same `setup()` the zoom driver already uses. |
| T-21-06-C | Tampering | Slide tap surface (D-10) | low | mitigate | Unchanged from plan 21-04's disposition: navigation is native anchor behaviour on a build-time-rendered internal href, so there is no synthesized open path and no coordinate-based exclusion guard that could be got wrong. Task 2 case 7 asserts the navigation target matches the slide's own href. |
