<objective>
Close UAT gap 2 (the zoom-to-slide handoff glitch): replace the deck driver's scroll-event-driven, rAF-batched update AND its asynchronous IntersectionObserver arrival reveal with ONE continuously-running requestAnimationFrame loop that re-polls live geometry every painted frame while attached.

Purpose: `21-UAT.md`'s second gap has a confirmed (not hypothesised) root cause — three independently-timed systems are all designed to reach their done state at the identical scroll offset (`trackTop = -900px`, which is also the page's first `scroll-snap-stop: always` boundary): native `position: sticky` release (paint-synchronous, always correct), the JS crossfade/`data-zoom-active` flag (waits on `scroll` dispatch), and the `is-revealed` arrival reveal (waits on `IntersectionObserver` callback delivery). On real iOS Safari, `scroll` dispatch and observer callbacks are throttled/coalesced during momentum and snap-settling, so the composited scroll position advances past t=1 before the JS catches up — producing the recorded frame where a stale, greatly-scaled wordmark cutout of gallery 1's photo overlaps the already-arrived flat cover-crop of the same photo, with no header, no accent panel and no title.

The fix collapses the two JS-driven systems into a single paint-synchronous loop, so all three finish states land on the same frame. This is deliberately a mechanism change, not a threshold tweak: `21-05-SUMMARY.md` and `21-06-SUMMARY.md` both independently flagged that neither Playwright project can reproduce the real-device physics, so tuning a number against an emulator would prove nothing — removing the event dependency altogether is what makes the timing correct by construction.

Scope note (why the observer goes too, not just the scroll handler): `21-UAT.md`'s root_cause names the `IntersectionObserver` arrival reveal as system 3, and the recorded bad frame shows the missing accent panel/title that only system 3 controls. Fixing system 2 alone would leave the reveal still lagging, so the failed truth ("the zoom-to-first-slide handoff is visually clean") would remain false. Driving arrival from the same loop is also strictly simpler code than keeping two mechanisms in sync.

D-02, D-03, D-04, D-09, D-12, D-13, D-14 and D-15 are all preserved exactly — this changes WHEN the state is computed, never WHAT the state is. D-14's "arrival-complete" semantics stay identical (a near-1.0 visible ratio on a full-viewport slide), just polled instead of pushed. `21-RESEARCH.md` Pattern 4's own note already anticipated revisiting the mechanism "if real-device testing shows this ratio flapping" — real-device testing did.

Output: a new pure export plus unit tests in `src/lib/home-carousel.ts` / `tests/unit/home-carousel.test.ts`, a rewritten driver lifecycle in `src/components/HomeCarousel.astro`, and new cases in `tests/e2e/homepage-scroll-deck.spec.ts`.
</objective>

  <behavior>
    `computeSlideVisibleRatio(rect, viewportHeight)` returns the 0..1 fraction of a full-width deck section that is currently visible in the viewport. `rect` is anything with numeric `top`, `bottom` and `height`; `viewportHeight` is a positive number.

    - Fully covering the viewport (top 0, bottom 852, height 852, viewport 852): returns 1.
    - Completely below the viewport (top 852, bottom 1704, height 852, viewport 852): returns 0.
    - Completely above the viewport (top -852, bottom 0, height 852, viewport 852): returns 0.
    - Exactly half scrolled in (top 426, bottom 1278, height 852, viewport 852): returns 0.5.
    - Exactly half scrolled out (top -426, bottom 426, height 852, viewport 852): returns 0.5.
    - Taller than the viewport but fully covering it (top -100, bottom 900, height 1000, viewport 852): returns 1 — the denominator is `min(rect.height, viewportHeight)`, NOT `rect.height`, so a section that is taller than the visible area can still reach the arrival threshold. This is the one deliberate divergence from `IntersectionObserver`'s own `intersectionRatio` semantics (which would cap that case at 0.852 and make the 0.98 threshold permanently unreachable) and it removes a real failure mode on a phone whose live viewport height disagrees with the section's own resolved height.
    - Degenerate `viewportHeight <= 0`: returns 0 (never divide by zero, never report a spurious arrival).
    - Degenerate `rect.height <= 0`: returns 0.
    - The result is always clamped to [0,1].
  </behavior>
