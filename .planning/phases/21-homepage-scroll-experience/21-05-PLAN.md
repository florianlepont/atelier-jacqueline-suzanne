<objective>
Wire the wordmark-to-photo zoom: a new, independent, rAF-batched scroll driver gated to phone width and no-reduced-motion, consuming the pure functions plan 21-01 already unit-tested.

Purpose: HOME-15 and phase success criterion 4 require the zoom to be visible and scroll-driven, and D-04 requires it to be fully reversible rather than a one-shot intro. `21-PATTERNS.md` identifies `DetailHero.astro` lines 198-322 as the codebase's canonical pinned scroll-scrubbed driver; this is that same driver with the breakpoint direction inverted and a scale/opacity payload instead of a width/position tween. Sketch 015 validated the payload on a real phone; plan 21-01 turned it into tested functions. What remains is glue: measure, batch, apply, detach.

Output: one new `<script>` block in `src/components/HomeCarousel.astro`, and new cases appended to `tests/e2e/homepage-scroll-deck.spec.ts`.
</objective>

    4. `syncFocusOrigin()`: reads the wordmark's and the focus span's bounding rects, passes them to `computeFocusOrigin`, and writes the returned pair as a percentage `transform-origin` on the wordmark. Returns without writing when the helper returns null.
    5. `onProgress(t)`: calls `computeWordmarkZoomState(t)` and applies `scale(...)` as the wordmark's transform, the wordmark opacity, and the photo layer's opacity. It also writes the zoom-active attribute on the `.home` root — set when progress has not yet reached 1, cleared to the completed value once it has. That attribute is the sole driver of D-12's header hide; the CSS for it already exists from plan 21-04.
    6. `onScroll()`: rAF-batched exactly as `DetailHero.astro` does — bail if a frame is already queued, otherwise queue one that clears the id and calls `onProgress(computeZoomProgress(track.getBoundingClientRect().top, ZOOM_REVEAL_DISTANCE))`.
    7. `clearInlineStyles()`: removes every property `onProgress` writes — the wordmark's transform, transform-origin and opacity, the photo layer's opacity — and removes the zoom-active attribute entirely from the root. Every write in `onProgress` must have a matching removal here; add a comment saying so, because the CSS end state for reduced motion depends on it.
    8. `setup()`: when reduced motion matches OR phone width does not match, detach the scroll listener if attached, cancel any queued frame, and call `clearInlineStyles()`. Otherwise attach the scroll listener with `{ passive: true }` if not already attached, call `syncFocusOrigin()`, and immediately run one `onProgress` pass from the current scroll position so a mid-page reload paints the correct state.
    9. Invoke `setup()` once, then register it as the `change` listener on BOTH media queries (a mid-session OS reduced-motion toggle, or a viewport resize crossing the breakpoint, must re-run the gate rather than being read once at load).
    10. Re-measure the origin after fonts settle: guard on `document.fonts` existing, then `document.fonts.ready.then(...)` calling `syncFocusOrigin()` only when the driver is currently attached. Measuring while the display font is still swapping produces a visibly wrong anchor — this exact mistake cost the sketch process an entire round.
    11. Re-run `setup()` on a debounced `resize` and on `orientationchange`, reusing `DetailHero.astro`'s `clearTimeout`/`setTimeout(…, 100)` idiom rather than introducing a `ResizeObserver`.
