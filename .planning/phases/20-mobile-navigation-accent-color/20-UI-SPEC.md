# Phase 20 — UI Design Contract

> Visual and interaction contract for Phase 20 (Mobile Navigation & Accent Color — HOME-13, HOME-16). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Consumed alongside `20-CONTEXT.md` (decisions D-01..D-05) and `20-RESEARCH.md` (technical architecture) — this file is the VISUAL/COPY layer only; do not re-derive architecture already settled in RESEARCH.md.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — this project has no shadcn/component-library dependency by design. Astro static build, hand-authored `.astro` components, plain CSS custom properties as the design-token system (defined in `src/layouts/BaseLayout.astro`). CLAUDE.md's near-zero-cost/static-only constraint and this milestone's own zero-new-dependency RESEARCH.md finding both confirm introducing shadcn/React/Tailwind here would be a regression, not an improvement — no gate question was asked of the user because every upstream constraint already answers it "no." |
| Preset | not applicable |
| Component library | none |
| Icon library | none — hand-authored. Existing header icons (globe in `LanguageSwitcher.astro`, Instagram glyph in `SiteHeader.astro`) are static inline `<svg>`. The NEW hamburger↔X toggle is the one exception: build it as a CSS-drawn 3-bar `transform`-morph (three `<span>` "bars", not an SVG), following the same "geometry-only CSS transition" principle already established by `HomeCarousel.astro`'s `.home-toggle__morph` — do not port that component's literal CSS-grid markup (shaped for a different glyph pair), and do not reach for an icon library. |
| Font | `--font-sans` (system stack: `-apple-system, BlinkMacSystemFont, 'Segoe UI', Helvetica, Arial, sans-serif`) for body/label text; `--font-display` (`'Unbounded'` via `@fontsource/unbounded`, weight 900 file loaded, `var(--font-sans)` fallback) for headings/display — both already defined in `BaseLayout.astro`, reused verbatim, no new font introduced. |

## Spacing Scale

Declared values (already established site-wide in `BaseLayout.astro` — reused verbatim, not re-specified):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/label internal gaps |
| sm | 8px | Compact element spacing (existing `.switcher-link`/`.nav-link` padding) |
| md | 16px | Default element spacing (`.chrome-band` padding) |
| lg | 24px | Section padding |
| xl | 32px | **Vertical gap between the mobile nav panel's big stacked primary list items** (Éditions / About / Contact / Language switcher) |
| 2xl | 48px | **Bottom offset for the secondary Instagram line** (distance from the panel's bottom edge, so it reads as "near the bottom," per D-04/reference) |
| 3xl | 64px | Page-level spacing (not used by this phase's new markup) |

Exceptions:
- `--tap-target-min: 44px` (already-established WCAG 2.5.5 floor) applies to BOTH the hamburger button (closed state) and the duplicated X-close button (inside the dialog, per Pattern 3 in RESEARCH.md) — same rule as every other interactive control site-wide, not a new exception.
- The mobile-nav `<dialog>` itself uses `padding: 0` (full-bleed, edge-to-edge), matching `Lightbox.astro`'s own `dialog#lightbox` precedent exactly — 0 is a valid point on the 4px grid, called out here only so the executor doesn't "fix" it by adding padding.
- No other exceptions.

## Typography

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Label (secondary Instagram line, existing `.nav-link`/`.switcher-link` shape) | 14px | 400 (regular) | 1.5 | `--font-sans` |
| Body (not used by new markup this phase; listed for completeness) | 16px | 400 (regular) | 1.5 | `--font-sans` |
| Heading (not used by new markup this phase; listed for completeness) | 20px | 600 (semibold) | 1.2 | `--font-display` |
| Display — **primary stacked nav list** (Éditions / About / Contact / Language switcher) | 32px | 600 (semibold) | 1.2 | `--font-display` (`'Unbounded'`) |

Exactly 4 sizes, 2 weights — identical to the site's pre-existing global type scale (`--text-label-*`/`--text-body-*`/`--text-heading-*`/`--text-display-*` in `BaseLayout.astro`). No new size/weight is introduced for this phase; the reference image's "big bold stacked list" (D-02) is achieved by applying the site's ALREADY-largest declared role (Display: 32px/600/Unbounded) to each nav item, centered, one per line — Unbounded's wide, heavy letterforms at 32px read as visually large/bold on a phone viewport without inventing a 5th size token.

The language-switcher item, when rendered as a primary list entry inside this panel, must be restyled to this SAME Display role (currently it renders at Label size/weight in `LanguageSwitcher.astro`'s own scoped `<style>` — see Color section below for how to override this without leaking the change to every other page).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`--color-dominant` / `--gray-0`) | Mobile-nav panel background — matches D-02's reference "white/light background" exactly; same token the rest of the site already uses for its dominant surface. |
| Secondary (30%) | `#FFFFFF` (`--color-secondary`, already merged into dominant site-wide per an earlier D-04 decision — header/footer are white-on-white) | Not separately used by this phase's new markup; listed for completeness/consistency. |
| Accent (10%) | `#D6327C` (`--color-accent` / `--pink-600`) — **the site's default UI accent everywhere EXCEPT the homepage hero/carousel surface** | Reserved for: focus-ring outlines (`outline: 2px solid var(--color-accent)`) inside the mobile-nav panel. NOT used for the primary nav-list text color or the language-switcher item once it moves into this panel (see below) — those render in ink, not accent, so all four primary items read as equal-weight per D-04. |
| Destructive | not applicable | No destructive action exists in this phase (pure nav-menu + accent-color feature; nothing to confirm/undo). |

**Homepage-only dynamic accent (HOME-16):** On the homepage hero/carousel surface specifically (separate from the mobile-nav panel above), `--current-accent`/`--current-accent-text` are NOT the static `--color-accent` — they are driven per-gallery from the fixed `HERO_COLORS` palette already defined in `src/lib/site-config.ts` (`pink #FF3B94`, `purple #AF3DFF`, `teal #55FFE1`, `lime #A6FD29`, `plum #37013A` — five values total, no sixth may be added, per REQUIREMENTS.md's explicit "no new palette" Out-of-Scope guard). This phase's ONLY change to that existing mechanism is which of the five is picked as the STARTING value on page load (random per visit, per D-05) instead of always defaulting to gallery 0's — the per-gallery-follows-carousel-position behavior on swipe/click/auto-advance is unchanged. Text-on-accent contrast (`getHeroTextColor()`, resolving to `#1A1A1A` ink or `#FFFFFF` white per accent) is also unchanged and reused as-is for whichever gallery is randomly picked.

**Primary/secondary nav-list text color:** All items inside the mobile-nav panel — Éditions, About, Contact, the language switcher, AND the secondary Instagram line — render in `--color-ink` (`#1A1A1A`), not accent pink, matching the reference's plain black-on-white treatment and D-04's "equal weight" framing for the language switcher specifically. This is a deliberate, scoped override of `LanguageSwitcher.astro`'s own default `.switcher-link { color: var(--color-accent); }` rule (pink, used everywhere else it's rendered) — apply it via a selector with the ENTIRE ancestor-through-target chain wrapped in one `:global(...)` (e.g. `:global(.mobile-nav-panel .switcher-link) { color: var(--color-ink); }`), per RESEARCH.md Pitfall 2 / `19-PATTERNS.md`'s already-documented fix shape for this exact class of Astro scoped-style bug. Do NOT wrap only the ancestor half of the selector in `:global()` — that compiles but can never match.

Accent reserved for: focus-ring outlines only, inside this phase's new mobile-nav markup. (Site-wide, `--color-accent` is also used for default links/language-switcher color on every OTHER page — unchanged, out of this phase's scope.)

This phase has no CTA/empty-state/error-state/destructive surface in the traditional sense — it is a navigation-affordance + accent-color feature. The table below covers the toggle's accessible names (its closest equivalent to a "primary CTA") in both site locales, matching the plain, direct sr-only phrasing convention already established in `LanguageSwitcher.astro` ("Passer en anglais" / "Switch to French").

| Element | Copy |
|---------|------|
| Primary CTA (hamburger button, closed state) | `aria-label`: FR "Ouvrir le menu" / EN "Open menu" |
| Primary CTA (X-close button, open state, duplicated inside the dialog per Pattern 3) | `aria-label`: FR "Fermer le menu" / EN "Close menu" |
| Empty state heading | not applicable — no list/data-driven empty state in this phase |
| Empty state body | not applicable |
| Error state | not applicable — no form, fetch, or user input in this phase's new surface |
| Destructive confirmation | not applicable — no destructive action in this phase |
| Nav item labels (primary list) | Reuse the EXISTING localized labels already passed into `SiteHeader.astro` verbatim: `editionsLabel`, `aboutLabel`, `contactLabel` (from `resolveSiteCopy()` in `src/lib/site-config.ts`) — do not introduce new copy strings for these. |
| Language-switcher item label (inside panel) | Reuse `LanguageSwitcher.astro`'s existing `targetLabel` ("EN"/"FR") + its existing sr-only `switchHint` ("Passer en anglais"/"Switch to French") verbatim — only its VISUAL size/color changes (Display role, ink color, per Color/Typography above), not its copy or link/cookie logic. |

## Interaction & Motion Contract

(Non-template section, added because this phase's D-03/D-02 discretion items are visual/motion decisions the checker and executor both need pinned down precisely — not left as open technical questions.)

| Aspect | Contract |
|--------|----------|
| Open transition | Pure CSS: `opacity 0→1` + `transform: translateY(-8px)→translateY(0)`, `220ms ease`, via `@starting-style` + `transition-behavior: allow-discrete` on the `<dialog>` (Baseline-safe on both this project's tested engines, Chromium + Safari 17.5+/WebKit, per RESEARCH.md Pattern 2). |
| Close transition | JS-orchestrated (NOT `@starting-style`/`allow-discrete` — Safari does not reliably animate the close side): add an `.is-closing` class → same `220ms ease` opacity/transform reverse → `transitionend` → THEN call `dialog.close()`. Mirrors `Lightbox.astro`'s existing `closeWithMorph()` shape exactly. |
| Reduced motion | `prefers-reduced-motion: reduce` → `transition: none` on the dialog (instant open/close, no transform) — same convention already used by `PageTitleHeader.astro`'s halftone drift and `.home-toggle__morph`. |
| Hamburger↔X icon morph | 3-bar CSS `transform`-only morph (rotate/translate the three bars into an X), same `~220ms` timing as the panel transition so both read as one coordinated motion. Gated behind the same `prefers-reduced-motion` check — reduced-motion users get an instant glyph swap, no rotation. |
| Halftone accent (D-02 discretion, resolved) | REUSE the exact existing dot-pattern values verbatim from `PageTitleHeader.astro`'s `.page-title-header__halftone` — `radial-gradient(rgba(26, 26, 26, 0.16) 1.4px, transparent 1.6px); background-size: 9px 9px;` — plus its existing subtle drift/fade-in animation (same `prefers-reduced-motion` gating it already has). Position: top-right corner of the mobile-nav panel (matching the reference image's corner placement). Re-derive the CONTAINMENT/positioning geometry fresh for the dialog's own `100vw`/`100vh` box (per RESEARCH.md Open Question 1) — do NOT port `PageTitleHeader`'s viewport-relative centering constants, which are tuned for a different element's position/max-width context. |
| Backdrop-click-to-close | Same pattern as `Lightbox.astro`: only a click where `e.target === dialog` (the dialog's own backdrop area, not a descendant) triggers close. |
| Escape-to-close | Native `cancel` event (fires on Escape), `preventDefault()`'d so the close transition can run before the real `dialog.close()` — same as `Lightbox.astro`. Do not add a separate `keydown` listener. |
