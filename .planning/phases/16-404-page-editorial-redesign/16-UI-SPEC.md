## Spacing Scale

Reuses the site-wide scale verbatim (`BaseLayout.astro` `:root`) — no new tokens introduced:

| Token | Value | Usage on this page |
|-------|-------|-------|
| xs | 4px | Gap between the "404" marker and its own letter-spacing rhythm; gap between link separator glyph and link text |
| sm | 8px | Gap between logo and "404" marker; gap between marker and phrase |
| md | 16px | Gap between phrase and the home-links row; horizontal padding of the centered content block on mobile |
| lg | 24px | Vertical padding around the centered content block; gap between the two home links (fr | en) in the side-by-side row |
| xl | 32px | Safe-margin from viewport edge for the centered block on small screens |
| 2xl | 48px | Not used on this page (no major section break — single-viewport composition) |
| 3xl | 64px | Not used on this page |

Exceptions:
- **Logo size**: `--tap-target-min` (44px) and the header's 56px logo do not apply here — D-06 explicitly requires "much larger than the header's 56px." Declare **120px width on mobile, clamp to 160px on desktop** (`clamp(120px, 14vw, 160px)`), preserving the asset's native aspect ratio. This is a one-off hero-scale exception, the same category of exception `DetailHero.astro`'s `--text-display-size` overrides already use on this site (a clamp() replacing a flat token where the token would be too small for a hero-scale moment).
- **Pool `<img>` stack**: `position: absolute; inset: 0` — full-bleed, not spacing-scale-governed (background layer, not a content-flow element).
- **Touch target**: the two home links must each still meet `--tap-target-min` (44px) tap-height on mobile despite the compact layout — pad the `<a>` hit area even though the visible text is small, matching the site's existing accessibility floor.

## Typography

Reuses the site-wide type-role tokens verbatim — no new sizes/weights introduced (site already declares exactly 4 sizes / 2 weights):

| Role | Size | Weight | Line Height | Usage on this page |
|------|------|--------|-------------|------|
| Label | 14px (`--text-label-size`) | 600 semibold (`--text-label-weight` override — see note) | 1.5 (`--text-label-leading`) | The "404" marker AND the two home-link labels. Render both **uppercase, letter-spacing 0.06–0.08em**, matching `DetailHero.astro`'s existing `.detail-hero__caption`/`.detail-hero__scroll-hint-label`/`.detail-hero__format` convention for small all-caps labels over photo backgrounds — do not invent a new small-label treatment. |
| Body | 16px (`--text-body-size`) | 400 regular | 1.5 | Not used in the primary composition (layout is deliberately more compact than the current page's paragraph copy — CONTEXT.md D-12). Reserved only for the `<noscript>`/no-JS fallback text if a longer sentence is needed there. |
| Heading | 20px (`--text-heading-size`) | 600 semibold | 1.2 | Not used — this page has no secondary heading tier; the bilingual phrase is the Display role instead (see below), not Heading. |
| Display | `clamp(28px, 5vw, 40px)` (phase-specific clamp built on `--text-display-family`/`--text-display-weight`, narrower range than `DetailHero.astro`'s `clamp(40px, 6vw, 72px)` reveal-title since this phrase is two short bilingual lines stacked, not a single gallery title) | 600 semibold | 1.2 | The bilingual "Page introuvable / Not found" phrase — the single highest-impact text element per CONTEXT.md's `<specifics>` ("high-impact and distinctive... a deliberate departure from the quiet, minimal treatment"). |

Copy layout for the phrase: two stacked short lines (FR then EN, e.g. "Page introuvable" / "Not found"), both at the same Display size/weight — not one language larger than the other, since neither is the "primary" locale on this un-routed page (structural constraint: FR+EN must both appear on every load).

## Color

Reuses the site-wide semantic tokens verbatim — no new hex values introduced:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60% equivalent) | The rotating full-bleed photo pool itself (not a flat token — CONTEXT.md D-03) is the page's dominant visual surface. `--color-ink` (`#1A1A1A`, `--gray-900`) is the fallback background behind/before the first pool `<img>` paints (prevents a white flash on slow connections). |
| Secondary (30% equivalent) | The dimming scrim — an absolutely-positioned overlay adapted from `DetailHero.astro`'s `.detail-hero__scrim` technique but **radial/uniform**, not `DetailHero`'s bottom-anchored `linear-gradient(to top, ...)` (RESEARCH.md Anti-Patterns explicitly warns the bottom-heavy gradient under-dims a **centered** composition). Build from `--color-ink` at graduated opacity: `radial-gradient(ellipse at center, rgba(26,26,26,0.72) 0%, rgba(26,26,26,0.55) 45%, rgba(26,26,26,0.35) 100%)` — strong enough at center for white text legibility over any pool photo, still showing photo detail at the edges. |
| Accent (10%) | `--color-accent` (`--pink-600`, `#D6327C`). Reserved for exactly: (1) the underline beneath the "404" marker (mirrors `.detail-hero__format`'s `border-bottom: 2px solid var(--color-accent)` convention), and (2) the `:hover`/`:focus-visible` state of the two home links. **Not** used on the logo, the phrase, or as a background fill anywhere on this page. |
| Destructive | not applicable — no destructive action exists on this page (site-wide convention is ink-only error styling, no red semantic token exists in this codebase per `BaseLayout.astro`'s own comment: "destructive-red semantic token is removed entirely"). |

Text-over-scrim color: `#FFFFFF` (white) for the logo (white variant `logoWhiteSrc`), marker, phrase, and links — matching `DetailHero.astro`'s white-on-scrim convention (`color: #FFFFFF` throughout `.detail-hero__overlay-title`/`.detail-hero__reveal-title`/`.detail-hero__format`). Logo variant selection (black vs. white) and any per-photo swap is Claude's Discretion per CONTEXT.md — default to the white variant (`logoWhiteSrc`) unconditionally, since the scrim guarantees sufficient contrast against every pool photo without needing per-photo color analysis.

Accent reserved for: **"404" marker underline, home-link hover/focus states.** Never the logo, never the phrase, never a background fill.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Retourner à l'accueil" (FR) / "Return home" (EN) — preserved verbatim from the current page per CONTEXT.md D-12 (meaning must survive, exact byte-for-byte wording is not required). Rendered as two links, side by side (D-06), separated by a thin vertical divider or middot (`·`), each individually reachable by keyboard/screen reader. |
| "404" marker | "404" — small, uppercase-style label treatment (Label role, letter-spaced), positioned between the logo and the phrase (Claude's Discretion per CONTEXT.md — logo on top, marker directly below it, phrase below that, links row last, so the eye reads logo → error code → message → escape route). |
| Bilingual phrase | "Page introuvable" / "Not found" — condensed from today's two-sentence-per-language copy (D-12 explicitly permits this: "the layout is far more compact... some condensing... is expected and fine"). No explanatory second sentence is required; the marker + phrase + links together already carry "this page doesn't exist, here's how to get home" in both languages. |
| Empty/edge state | If `getGalleries()` returns zero usable photos at build time (empty Sanity dataset edge case — not expected in practice, but must not crash the build), fall back to a flat `--color-ink` background with no pool `<img>` stack at all; the centered content (logo/marker/phrase/links) renders identically regardless. This is the page's only "empty state" — there is no user-facing empty-data state otherwise, since D-06's content block never depends on runtime data. |
| Error state | The 404 condition itself IS the error state being communicated — no separate error-within-error copy is needed. HTTP 404 status is served correctly by `public/.htaccess` unchanged; `noIndex` meta and `<title>` on `BaseLayout` stay as-is per CONTEXT.md's `<code_context>` (only body content changes). |
| Destructive confirmation | not applicable — no destructive action exists on this page. |

## Interaction & Accessibility Notes (context, not a new contract — see CONTEXT.md/RESEARCH.md for full detail)

These are already fully locked by `16-CONTEXT.md` (D-08 through D-11) and `16-RESEARCH.md` (Patterns 3-5); restated here only so the visual contract above is read in context, not as new decisions:

- Photo-swap is a **hard cut** (opacity/z-index toggle, no CSS `transition` declared) — the Design System/Color sections above assume this; do not add a crossfade to "smooth out" the scrim or logo.
- Max pop rate is capped at ≈3 changes/second (`MIN_INTERVAL_MS ≈ 350ms`) — this is an accessibility floor, not a visual-design knob; it does not change any value in this UI-SPEC.
- `prefers-reduced-motion` shows a slow constant drift (not a freeze) — the visual composition (logo/marker/phrase/links, scrim, type sizes) is identical in both motion states; only the background photo's *change cadence* differs.
- All pool `<img>` elements get `alt=""` and the pool container gets `aria-hidden="true"` (RESEARCH.md Pitfall 6) — the accessible content tree is exactly the logo (decorative, `alt=""`, since the phrase text already conveys the brand-return meaning), the "404" marker, the phrase, and the two links.
