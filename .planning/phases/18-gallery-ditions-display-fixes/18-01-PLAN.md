## Correction to CONTEXT.md D-04 and 18-PATTERNS.md (read before Task 1)

CONTEXT.md D-04 and 18-PATTERNS.md both assert that all 4 detail pages use `GalleryGrid` in its
default bento / `object-fit: cover` mode, and that the masonry / `object-fit: contain` code path
"is not live anywhere currently".

**That is factually wrong.** Verified against the source during planning:

| Detail page | Renders via | GalleryGrid call | Live mode | `.tile img` treatment |
|---|---|---|---|---|
| `/galleries/{slug}/` + `/en/galleries/{slug}/` | `src/components/GalleryDetailBody.astro` line 63 | passes `layout="masonry"` | **masonry** | `position: static`, `aspect-ratio: var(--ar)`, `object-fit: contain` |
| `/editions/{slug}/` + `/en/editions/{slug}/` | `src/components/EditionDetailBody.astro` line 79 | passes no layout prop | **bento** (default) | `position: absolute; inset: 0`, `object-fit: cover` |

**BOTH code paths are live, one per content type.** Consequences for this plan:

1. D-04's *conclusion* is unchanged and still correct — the frame lives on the shared `.tile` base
   rule (line 207), which applies in both modes, so one deletion still fixes all four pages. No
   user decision changes.
2. D-04's *reasoning* ("masonry is not live, don't spend effort on it") must be discarded.
   Verification MUST cover both modes: a gallery detail page (masonry) AND an edition detail page
   (bento). Testing only one proves half the requirement.
3. In masonry mode `object-fit: contain` means the retained background (D-05) would show as
   letterbox bars whenever a tile's `--ar` disagrees with its image's intrinsic ratio. Checked
   against live content during planning: `src/pages/galleries/[slug].astro` line 76 computes
   `aspectRatio` from the real `img.dimensions`, grid `src`/`srcset` use the UNCROPPED helpers, and
   a live GROQ count confirms **0 of 36 gallery images are missing `metadata.dimensions`**. So
   contain fits exactly and no letterbox exists today. Keeping the background per D-05 is safe.

Record this correction in the SUMMARY so the phase verifier does not re-derive it.
