<scope_notes>
Findings from planning-time investigation that change what the executor must do — read before starting:

1. **CONT-03 needs NO `::before` compensation.** An absolutely-positioned child's `inset: 0` resolves against its containing block, which is the *padding box* of the nearest positioned ancestor (`.contact-page__detail` is `position: relative`). Adding horizontal padding to `.contact-page__detail` therefore does NOT shrink `.contact-page__detail::before` — the fill keeps spanning the full row. D-07's second listed option ("having `::before` fill the full row while the visible content gets the padding") is what happens naturally, so `inset: 0` stays untouched. This must be **measured, not assumed** (acceptance criteria below), with the negative-inset variant as the documented fallback if the measurement disagrees.
2. `.contact-page__detail` has `overflow: hidden` (line 149), which clips at the padding box — a negative-inset `::before` would be clipped anyway, which is a second reason the fallback is a fallback and not the primary.
3. **EDN-09's `::before` rule has one syntax risk.** `:global(html.editions-row-active .page-title-header__eyebrow::before)` puts a pseudo-element inside `:global()`. If Astro's scoped-CSS transform mishandles it, the equivalent `:global(html.editions-row-active .page-title-header__eyebrow)::before` is the fallback. The e2e assertion on the dot's `background-color` is what distinguishes the two — do not skip it.
4. Cascade check (done at planning time, no action needed): each corrected selector resolves to a higher specificity than PageTitleHeader.astro's own scoped base rule, so the override wins regardless of stylesheet order. Eyebrow/intro `(0,2,1)` vs `(0,2,0)`; `h1` and `::before` `(0,2,2)` vs `(0,2,1)`; divider `(0,2,1)` vs `(0,2,0)`.
5. `.page-title-header__divider` is `display: none` below 760px — any divider assertion must run at a >=760px viewport.
</scope_notes>
