<interface_context>
Contract this plan consumes, owned by plan `05-01` (`public/contact.php`, same wave — do NOT edit that file here):

- `POST` with fields `name`, `email`, `message`, `website` (honeypot).
- Success: HTTP 200, body `{"success": true}`.
- Failure: HTTP 400 / 405 / 502, body `{"success": false, "message": "…"}`.
- Cross-origin reads are permitted only from the exact origin `https://florianlepont.github.io` (the endpoint emits `Access-Control-Allow-Origin` for that origin alone).
- Because the endpoint reads `$_POST`, the request body must be `multipart/form-data` or `application/x-www-form-urlencoded` — a JSON body would arrive as an unparsed raw stream and every field would read as empty. Sending the existing `FormData` object directly satisfies this AND stays CORS-safelisted, so no preflight `OPTIONS` request is generated.

Existing shapes in `src/components/ContactForm.astro` that must not change (a visual regression baseline at `tests/e2e/visual.spec.ts-snapshots/contact-form.png` covers the rendered form): all markup, all CSS, all localized copy, the honeypot input's `name="website"`, the per-field validation flow, the `isSubmitting` re-entrancy guard, and the `try/catch/finally` wrapper. Only the frontmatter constant, one new `data-*` attribute, and the inner `fetch()` call change.

Local build/e2e note: `.env` is absent from this worktree (it is gitignored) but exists at `/Users/florian/Projects/ajs-website/.env`. Copy it in before running Playwright, since `npm run preview` requires a build and the build requires the Sanity credentials.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Pages origin → OVH `contact.php` origin | A cross-origin browser request carrying visitor-supplied data. |
| build-time env (`PUBLIC_CONTACT_ENDPOINT`) → client bundle | The value is baked into public JavaScript and is therefore world-readable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-11 | Tampering | cross-origin submission path | low | mitigate | Server-side allowlist in `public/contact.php` (plan `05-01`) admits exactly one foreign origin. This plan's contribution is to keep the request CORS-safelisted (FormData body, no manual `Content-Type`) so the browser's own CORS enforcement applies rather than being bypassed by a preflight the server would have to answer permissively. |
| T-05-12 | Information Disclosure | `PUBLIC_CONTACT_ENDPOINT` in the client bundle | low | accept | The value is a public URL to a public endpoint; the `PUBLIC_` prefix makes the exposure explicit and intentional. No secret is ever placed in this variable — enforced by the `.env.example` acceptance criterion requiring an empty value. |
| T-05-13 | Spoofing | client-side validation bypass (direct POST to the endpoint) | medium | mitigate | Deliberately not addressed here. `src/lib/contact-form.ts` is a UX layer only; every check it performs is independently re-implemented server-side in `public/contact.php` (plan `05-01` Task 2 steps 6-10), which is the only enforcement point that matters. This plan must not weaken those server-side checks by moving validation client-side. |

No npm/pip/cargo packages are installed by this plan; the package-legitimacy gate is not applicable.
</threat_model>
