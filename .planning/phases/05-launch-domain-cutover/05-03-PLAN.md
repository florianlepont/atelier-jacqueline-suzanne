`username`, `server`, `port` (default `"22"`), `ssh_private_key`, `local_path` (default `./*`), `remote_path`, `sftp_only` (default `false`), `sftpArgs`, `delete_remote_files` (default `false`), `password`, `rsyncArgs`, `ssh_passphrase`.

Three corrections to RESEARCH.md that matter:

1. The password input is named **`password`**, NOT `ssh_password`. Using the wrong name silently falls through to the private-key code path and the deploy fails with a confusing key error.
2. `delete_remote_files: true` runs `ssh … rm -rf $remote_path` — it needs a real SSH shell, which OVH's mutualized tier does not have (Professional tier and up only). Leaving it at `false` is not merely a preference, it is a hard requirement. Consequence: uploads overwrite but never delete, so removed files linger on the server. Astro content-hashes its assets, so stale files are inert; this is accepted, not fixed.
3. `sftp_only: true` is what skips the action's `ssh … mkdir -p` step. It is mandatory here for the same no-shell reason.

The action's entrypoint ultimately runs `put -r <local_path> <remote_path>` inside an sftp batch. **`put -r ./dist/*` will not match `dist/.htaccess`** — glob expansion excludes dotfiles. That single behaviour would silently ship the site without its `ErrorDocument`, `Options -Indexes`, and HTTPS-redirect rules. It is handled below with a second, explicit upload step.

The action is a Docker action (`runs: using: docker, image: Dockerfile`), so the pinned commit's Dockerfile is built and executed on the runner with the SFTP password in scope. It also passes `-o StrictHostKeyChecking=no`, so the host key is not verified.

**`actions/upload-artifact@v4` excludes hidden files by default** (since v4.4). `include-hidden-files: true` is required or `.htaccess` never even reaches the deploy job.

**OVH SFTP facts** (from `01-02-SUMMARY.md`, re-stated in `05-CONTEXT.md`): host `ftp.cluster129.hosting.ovh.net`, user `atelihu`, port 22, SFTP only, password auth only (no SSH keys on shared hosting), home `/home/atelihu`. The webroot is expected to be `/home/atelihu/www` — this is the one value NOT independently confirmed, and plan `05-05`'s blocking checkpoint confirms it against the OVH panel before the first real push.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → OVH SFTP server | The runner authenticates with a long-lived password that grants write access to the entire hosting account's home directory. |
| third-party GitHub Action → runner with secrets in scope | A Docker action builds and executes code from an external repository in the same job that holds `OVH_SFTP_PASSWORD`. |
