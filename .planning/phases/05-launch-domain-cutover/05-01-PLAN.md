Create `public/contact.php`. Astro copies `public/` into `dist/` untouched, so this file needs no build integration. Write it for maximum PHP-version tolerance: OVH mutualized hosting does not let a site pin its PHP version, so use only PHP 7.0-compatible syntax — declare the helper's return type as `void` (NOT `never`, which requires 8.1), use `preg_match` rather than `str_contains`, and do not use `declare(strict_types=1)`.

Structure it in exactly this order (each step must precede the next, because the CRLF guard is only a defence if nothing has been concatenated into a header before it runs):

1. Emit `header('Content-Type: application/json; charset=utf-8');` as the first statement so every exit path is JSON.
2. CORS allowlist. D-03 keeps GitHub Pages alive permanently as pre-production, so the form will call this endpoint cross-origin from `https://florianlepont.github.io`. Sending the body as `multipart/form-data` (plan `05-02`) avoids a preflight, but the browser still refuses to let JavaScript READ the response without an allow-origin header — so without this block the staging form always falls through to the D-09 error message. Define a `$allowedOrigins` array containing exactly the one literal string `https://florianlepont.github.io`; read `$_SERVER['HTTP_ORIGIN']` with a `?? ''` default; and only if `in_array($origin, $allowedOrigins, true)` emit `Access-Control-Allow-Origin: ` concatenated with `$origin` plus a `Vary: Origin` header. Echo back only an allowlisted origin — never a wildcard, never the raw request origin unchecked. Do not emit `Access-Control-Allow-Credentials`. No `OPTIONS` handler is needed: `multipart/form-data` is CORS-safelisted, so no preflight is ever sent.
3. A `fail(int $code, string $message)` helper returning `void` that calls `http_response_code($code)`, echoes `json_encode(['success' => false, 'message' => $message])`, and `exit`s. Every rejection path goes through it so the response shape is uniform.
4. Method guard: if `$_SERVER['REQUEST_METHOD'] !== 'POST'`, `fail(405, 'Method not allowed')`.
5. Read and `trim()` four values out of `$_POST`, each with a `?? ''` default: `name`, `email`, `message`, and the honeypot key `website` (this key MUST match the honeypot input's `name` attribute in `src/components/ContactForm.astro` — verify by reading that file, do not assume).
6. Honeypot short-circuit (D-08 — the honeypot is the ONLY anti-spam layer; do not add rate limiting, CAPTCHAs, or content heuristics): if the honeypot value is not the empty string, echo `json_encode(['success' => true])` and `exit` WITHOUT sending mail. Return the success shape so the detection mechanism is never revealed, exactly as the client-side helper `isHoneypotTriggered` already does.
7. Required-field guard mirroring `isBlank`: if any of name/email/message is the empty string after trimming, `fail(400, 'Missing required field')`.
8. Length caps: if `strlen($name) > 200`, `strlen($email) > 254`, or `strlen($message) > 5000`, `fail(400, 'Field too long')`. This bounds the mail body an anonymous caller can generate (ASVS V5).
9. CRLF guard — the core header-injection defence. Loop over the three submitted values and `fail(400, 'Invalid input')` if `preg_match('/[\r\n]/', $field)` matches. This MUST run before any header string is built; a newline reaching the headers argument of `mail()` becomes a new header line, which is how `Bcc:` smuggling works.
10. Email format guard: if `filter_var($email, FILTER_VALIDATE_EMAIL)` is falsy, `fail(400, 'Invalid email address')`. Use the built-in filter rather than a hand-rolled regex.
11. Set `$to` to the exact literal address confirmed in Task 1 — do not substitute a code default. Set `$subject` to the fixed literal `Nouveau message depuis le site — Atelier Jacqueline Suzanne`.
12. Build `$headers`. The `From:` line MUST be a pure string literal on the site's own domain — use `no-reply@atelierjacquelinesuzanne.fr` — with no PHP variable anywhere on that line. The apex SPF record is `v=spf1 include:mx.ovh.com -all` (hard fail, verified live), so putting the visitor's address in `From:` would guarantee an SPF failure at the receiving Zimbra. The visitor's address goes in `Reply-To:` only, which is safe because steps 9 and 10 already proved it contains no CRLF and is a valid address. Add `Content-Type: text/plain; charset=UTF-8`. Join header lines with `\r\n`.
13. Build a plain-text `$body` containing the visitor's name, email, and message.
14. Call `mail($to, $subject, $body, $headers, '-f no-reply@atelierjacquelinesuzanne.fr')` exactly once. The fifth argument sets the envelope sender to the owned domain, which is what the receiving server's SPF check evaluates.
15. If the call returned false, `fail(502, 'Send failed')` — a non-2xx status is required so the client's existing failure branch fires and renders the D-09 fallback. Otherwise echo `json_encode(['success' => true])`.

Keep every comment in this file descriptive of intent. Do not paste example attack strings, sample `From:` header values, or "what not to do" snippets into comments — several assertions in the companion test scan this file's raw text and a commented-out counter-example would trip them.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser → `contact.php` | Fully untrusted input crosses here. This is the only request-time compute the site has; there is no auth, no session, no rate limit. |
| `contact.php` → OVH local MTA (`mail()`) | Attacker-influenced strings become mail headers and body. A newline here is a privilege escalation into the mail envelope. |
| `public/` build passthrough → GitHub Pages public artifact | Source authored for a PHP host is published verbatim on a host that cannot execute it. |
